# Security Policy

## Reporting a vulnerability

Please report vulnerabilities **privately** through GitHub's private vulnerability reporting: the repository's **Security** tab → **Report a vulnerability**. Do not open a public issue. A public reproduction is a working exploit handed to everyone.

Include what you found, how to reproduce it, and the version or commit you tested.

## What to expect

This is a one-person project maintained in spare time. Reports are read and acknowledged on a best-effort basis, typically within a couple of weeks. There is no guaranteed fix timeline, but you'll be kept informed, and credited in the advisory if you want to be.

## Known issues register

Security findings from the project's own audits are tracked as public issues under the [`security`](../../issues?q=label%3Asecurity) label. That register is for issues found internally. External reports go through private reporting first.
