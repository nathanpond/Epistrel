# `asymmetry`: provenance

- **Measures:** Q-04 (`q04`): knowledge-asymmetry violations, NFR-QUAL-1 (`nfr_qual_1.asymmetry`, observed-zero rule).
- **Authored by:** the builder (the owner's round-one decision on #157, kept for #179: the builder labels, the owner approves), on 2026-10-23, for #179.
- **How:** 384 questions whose correct answer requires not knowing another character's private fact, plus 32 negative controls. Four story fixtures (`src/epistrel/evals/fixtures.py`: S-FAMILY's Sunday Dinner, S-WHISPER's parlor, S-NESTED-BELIEF's knock, S-PHONE's kitchen), each with a player character, five modeled characters and eight hand-written private facts, each held by one character alone (a canon fact only its holder may read, and the holder's own `secret` belief in it). For every fact, every one of the four characters who do not hold it is asked about its topic with three fixed templates (a direct question, a leading statement, a gossip request): 4 x 8 x 4 x 3 = 384 cases, labeled `withheld`. Each case lists the fact's forbidden forms (its names, aliases and paraphrases), which the player-facing answer must not hold. The 32 controls (one per fact) ask the holder itself, whose scripted answer states the fact, labeled `control`: they show the oracle detects a disclosure. Each case carries the stub's clean answer (a render naming nothing private), written per template. The generator refuses a question, an answer or a topic that holds one of its own forbidden forms, and a fact whose paraphrased `leak` (E-08's injected violation) names its protected object. A template's first instance per fixture is `authored`, the rest `paraphrase`.
- **Generated by:** `src/epistrel/evals/authoring/asymmetry.py` (deterministic, template-driven; no model). `uv run python -m epistrel.evals author` regenerates the set; `--check-sets` fails when the committed file differs, so the set changes only through its reviewed module. Every case carries its `origin`: `authored` or `paraphrase`.
- **Review:** the owner reviews the digest (`docs/evals/sets-digest.md`, stratified by fixture and template) and records approval by replacing the line below with `approved by owner YYYY-MM-DD` in a commit of their own. Until then `--check-sets` passes on a branch and fails where approval is required (`EPISTREL_REQUIRE_APPROVED_SETS=1`). The set is approved before the local run measures on it.
